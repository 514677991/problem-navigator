# 常见问题

| 现象 | 检查方法 |
|---|---|
| 宿主不能导入 ZIP | 按照[通用入门](quickstart.md)使用宿主自己的技能发现或明确文件读取机制。唯一发行包包含可选 Codex 元数据，不是通用导入协议。 |
| 宿主没有按工作流执行 | 确认完整读取入口与必要阶段技能，可写入产物、运行 Python 工具并询问文档接受。纯聊天或只有 MCP 工具都不够。 |
| Codex 适配缺失或找不到 `codex plugin` | 按独立 [Codex 指南](../../adapters/codex/README.zh-CN.md)检查已安装 CLI 支持情况，启用适配并新建任务。 |
| MCP 只能在某个工作目录启动 | 通用命令应使用已安装 `mcp/web-research-mcp` 的绝对路径，不依赖某个宿主的 `cwd` 字段。 |
| 工具名称不同 | 发现实际名称与结构，宿主前缀可能不同。MCP 只暴露四个研究工具，不是完整工作流。 |
| 宿主只接受远程 HTTP MCP | 当前服务仅支持 stdio，不能直接通过该传输连接；没有内置托管端点。 |
| 找不到 `uv` | 确保桌面宿主自身的 `PATH` 能找到 `uv`，不能只检查当前终端；修改后重启。 |
| Python 或依赖解析失败 | 确认 Python 3.11+，并按照[入门指南](quickstart.md)运行锁定版本的 `uv sync`。首次安装需要下载。 |
| 离线启动检查无法启动 | 先对规范项目运行 `uv sync --locked --project mcp/web-research-mcp --extra dev` 准备依赖，再构建 ZIP，按开发指南使用 `--archive` 及 `--mode direct` 或 `--mode declared`。验证器子进程使用离线缓存。 |
| `NOT_CONFIGURED` | 配置所选路由对应的服务商，或明确选择兼容且已配置的路由。`NONE` 研究无需密钥。 |
| `config_state: "INVALID"` | 检查 UTF-8 JSON、整数 `schema_version: 1`、支持的字段与非空密钥。任一文件错误会使全部文件设置失效；环境变量密钥仍可能可用。 |
| 文件中的密钥被忽略 | 存在对应服务商环境变量时会覆盖文件，即使值为空或无效。检查变量是否存在时不要输出密钥。 |
| `AUTH_FAILED` | 在本地核对所选服务商密钥，替换已撤销或无效的凭据。已配置状态不等于线上认证测试通过。 |
| `RATE_LIMITED` 或 `QUOTA_EXHAUSTED` | 检查服务商账户与限制；服务还设有本地速率限制，连续立即重试可能加重限制。 |
| `INVALID_REQUEST` | 按照 [MCP 说明](../../mcp/web-research-mcp/README.md)检查路由与过滤条件兼容性、查询长度和公开 URL 要求。 |
| `NETWORK_ERROR` 或 `PROVIDER_ERROR` | 检查连接与服务商可用性，保留安全的错误码与请求 ID。系统不会自动切换服务商。 |
| `NO_RESULTS` 或证据被截断 | 缩小问题，或通过兼容且已授权的路由获取相关段落；保留证据缺口说明。 |
| 因产物缺失/无效而停止 | 保留工作流及引用产物；确认缺失或过期输入，再明确请求从有效保留输入重新生成。不要虚构历史或重置计数。 |
| 发行镜像一致性检查失败 | 修改核心/适配规范源文件，运行 `scripts/sync_plugin_payload.py --write`，再运行 `--check`。 |
| 布局验证器拒绝源仓库根目录 | 请传入生成镜像或 ZIP 解压目录；源仓库采用开发布局。 |

反馈问题时，请提供发行/MCP 版本、接入方式、宿主名称/版本、操作系统、Python/uv 版本、脱敏后的最小复现、安全错误码/请求 ID，以及预期与实际行为。不要提供 API 密钥、完整配置文件、原始私人文档或敏感 URL。漏洞请按[安全流程](../../SECURITY.zh-CN.md)报告。

生成的分析仍可能包含缺乏支撑的推断。纠正时请指出受影响的具体结论；工作流应重新打开相关证据，并撤回过期的下游结果。自动检查通过不能替代事实审阅。
