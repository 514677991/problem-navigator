# 通用入门指南

## 1. 准备运行环境

需要能够完整读取 Markdown 技能文件、遵循引用、读写本地工作流产物并执行本地 Python 命令的 AI 宿主。宿主应能找到 Python 3.11+ 和 `uv`。原生技能支持便于使用，也可采用明确读取文件的集成方式。没有文件与命令访问能力的纯聊天环境无法执行完整工作流。

克隆源仓库或解压 `problem-navigator-2.1.0.zip`。保持 `skills/` 与 `mcp/` 位于同一安装根目录，在该目录检查：

```sh
uv --version
uv python find ">=3.11"
```

如果找不到命令，请先安装或配置对应环境。终端与 AI 宿主的环境可能不同；修改 `PATH` 或服务商环境变量后，重启宿主。

按照锁文件准备依赖：

```sh
uv sync --locked --project mcp/web-research-mcp
```

首次准备通常需要联网。离线研究并不意味着一台全新机器可以离线下载运行环境。

## 2. 加载工作流说明

让宿主完整加载 `skills/problem-navigator/SKILL.md` 入口文件，以及其中引用的工作流契约与产物结构。路由到其他技能时，从相邻目录加载该阶段完整的 `SKILL.md`。保留脚本和引用的位置；只复制入口正文会丢失必要依赖。

若宿主支持技能发现，请按照其文档注册这些技能目录。若没有技能机制，可先明确指示：

> 安装根目录为 `<绝对安装路径>`。读取其中完整的 `skills/problem-navigator/SKILL.md` 及其必需引用，然后按该工作流处理我的请求。从此安装目录解析相邻阶段技能，在我选择的工作区保存分析产物。

将路径替换为实际安装位置。`$problem-navigator`、`/problem-navigator` 等快捷语法属于宿主机制，并非核心要求。唯一 ZIP 包含可选 Codex 元数据，但不承诺可以在所有宿主中一键导入。

使用已提供的 Codex 适配时，见同一包内的 [Codex 安装指南](../../adapters/codex/README.zh-CN.md)，无需额外压缩包。Claude Code 或其他宿主应参考各自的技能与 MCP 文档，并在本地验证行为；此处没有内置其他原生宿主适配。

## 3. 运行离线示例

> 使用已加载的 problem-navigator 工作流，用中文回答。只使用我的记录：一个志愿读书小组需要在每周和每两周聚会之间做选择，尚未调查成员偏好。不要联网。先帮助我们理解这个决策，输出研究报告，将偏好和出席率估计标为未知。

预期行为：选择 `NONE`，澄清关键缺口，分析已有证据并给出报告预览。此过程不应检查服务商密钥或发起研究网络调用。报告准备好后，由你明确接受所审阅的版本，仍然保留其局限说明。

工作流保存在分析工作区的 `.problem-navigator/workflows/` 下。续接或备份时，请将工作流文件与其引用的产物作为整体处理。不要让多个进程同时写入同一工作流。

## 4. 为网页研究注册 MCP

按照[配置指南](configuration.md)，使用绝对安装路径注册 stdio 服务并提供自己的密钥。MCP 配置因宿主而异。单独注册仅提供四个研究工具，并不会安装第 2 步的技能工作流。

随后发起网页研究请求，让工作流检查所需能力是否已配置。本地状态响应仅能确认配置；只有真实请求才能检验线上认证与额度，该请求可能产生服务商费用。仅支持远程 HTTP MCP 的宿主无法直接连接此 stdio 入口。

若宿主提供内置工具，你也可以针对明确的研究范围授权使用。该方式独立于内置服务商路由，遵循宿主自身的账户与规则。

## 可选：离线使用已缓存依赖

第 1 步对规范项目执行的 `uv sync` 会准备依赖缓存。依赖和兼容的 Python 运行环境缓存完成后，本地命令可以使用 `uv` 的 `--offline` 选项。不要在源仓库的生成插件镜像内创建虚拟环境；开发检查要求该载荷与规范源一致。

压缩包启动验证器同样要求已缓存运行环境。`NONE` 仅保证该工作流不执行研究网络操作；AI 宿主可能仍需要正常的模型连接。
