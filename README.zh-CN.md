# Problem Navigator｜问题导航

把尚不清晰的通用问题或产品/软件问题，整理成有证据支撑的研究报告、决策与设计规格。由共享技能与本地 Python/MCP 研究核心组成，支持中文和英文。发行版本 **2.4.0**；研究 MCP **0.2.0**；[MIT 许可证](LICENSE)。

## 核心思路与八阶段

Problem Navigator 从问题定界、证据建立、价值澄清与方案选择，推进到方案完善、文档表达和规格拆分。法庭式对抗是第 5 阶段的选型方法；其他阶段分别保障问题、证据、需求和设计的质量。

下表把各阶段的操作规则与方法视角对应起来。第一性原理、苏格拉底式提问、奥卡姆剃刀等用于指导分析与审查；本地脚本负责其中可明确检查的产物、引用、版本和内容一致性。

| 阶段 | 核心方法 | 具体做法与质量作用 |
|---|---|---|
| [1. 问题定界](skills/problem-framing/SKILL.md) | **第一性原理、问题重构** | 从真实目标、必要约束与待验证假设出发，分清范围、非目标和交付结果。追问“真正需要达成什么”，避免把用户提出的某个解法直接当成问题本身。 |
| [2. 研究设计](skills/research-design-kickoff/SKILL.md) | **问题驱动、可证伪性、按相关性组织研究** | 将缺口转成可回答的研究问题；需要决策时，使问题能够区分候选。预先明确质量标准与停止条件，同时寻找支持和反证。按实际相关性合并或省略主题，让调研服务于判断。 |
| [3. 研究执行](skills/research-execution/SKILL.md) | **批判性思维、证据分级、独立核查** | 核对原文、来源独立性、日期和版本，区分事实、推断、假设与未知；推断必须有事实基础。避免把同一文章的多次检索当作多份独立证据，让结论可定位、可反驳、可纠正。 |
| [4. 决策准备](skills/decision-readiness-interview/SKILL.md) | **苏格拉底式提问、事实与价值分离** | 只追问会改变决策的意图、前提与取舍，如“为何这项约束重要”“哪种风险不可接受”。复用已有答案；公共事实缺口回到研究，用户价值由用户澄清，避免无效问卷和让用户猜事实。 |
| [5. 方案筛选](skills/adversarial-option-selection/SKILL.md) | **独立思考、批判性思维、法庭式对抗** | 先冻结评价标准，再独立建案、披露缺陷与反证、逐候选质询，最后由未参与辩护的独立法官裁决。用论据承受反驳的能力支持选择，避免附和、先入为主和凭票数选方案。 |
| [6. 方案完善](skills/solution-refinement/SKILL.md) | **第一性原理、奥卡姆剃刀、消融思路、What/How 分离** | 从目标与验收条件反推必要能力，按交付范围先明确 What，再约束需要设计的 How。逐项检查功能、组件、规则或流程的必要性，说明依赖、异常和代价；在同等满足目标与约束时减少无依据的假设与复杂度，保持已确认语义。 |
| [7. 正式文档](skills/solution-documentation/SKILL.md) | **语义保真、关注点分离、单一需求基线、可追溯性** | 将已明确的方案准确写入文档；需要产品与技术双文档时，技术设计引用当前需求与验收 ID。保持范围、例外和风险含义，验收实际版本，减少转写漂移、重复定义和交付错稿。 |
| [8. 规格拆分](skills/solution-decomposition/SKILL.md) | **高内聚低耦合、按需拆分、接口与契约意识** | 围绕独立目标和职责组织单元，显式说明边界、接口、依赖与验收映射。相关内容聚合在同一单元，跨单元关系清晰可审查；拆分无收益时保留单单元，避免碎片化和隐含依赖。 |

**苏格拉底式提问用于暴露关键前提。** 例如：“这条要求服务于哪个目标？”“它依赖什么依据？”“若前提不成立，方案如何变化？”“哪些例外或后果尚未考虑？”仅在答案会影响范围、选择或风险时追问，已有明确答案时直接复用。

**消融试验用于检验必要性与贡献。** 在方案完善中，可先用消融式追问：“移除这一功能、组件或审批环节，目标和验收是否仍能满足？”这属于反事实推演。需要实证时，定义基线、移除项、保持一致的条件和评价指标，并按需把问题纳入补证、读取真实试验记录。当前工作流不内置自动执行消融实验的引擎；未运行的实验只能写成待验证设计，不能当作已验证结论。

**奥卡姆剃刀约束不必要的复杂度。** 简化以目标、证据和约束仍得到满足为前提，不等于追求最短方案。可靠性、安全性与必要例外不能为了简洁被删掉，也不能借此擅自缩减已确认需求或改成 MVP；涉及选择或语义变化时返回对应阶段。

贯穿全链路的原则还包括：

- **保持独立思考，允许修正判断。** 不把用户偏好、权威说法、模型自信或多角色共识当作事实证明；对支持与反对材料采用一致标准，发现反证后更新结论。
- **按问题选择深度。** 通用问题围绕机制、利益相关者与约束；产品/软件问题按需求裁剪 What 与 How。`UNDERSTAND` 在第 3 阶段完成报告，`DECIDE` 继续决策与设计；第 8 阶段仅在约定需要规格包时执行。
- **阶段职责集中，通过明确产物衔接。** 研究设计、证据获取、价值澄清、选型、语义完善与文档表达各负其责；用稳定引用与版本衔接，减少跨阶段职责混杂。
- **可追溯、可纠错、诚实验收。** 事实变化重开受影响研究，保留计数并撤销过期下游引用；起草授权产生预览，接受的是实际审阅的文档版本。

这些方法需要宿主认真执行和判断。结构检查与哈希能够检查记录一致性，不能证明事实真实、实验已发生、架构已经最优、会话确实独立或用户实际接受了文档。

## 从问题生成可执行的调研任务书

产品/软件研究先核对项目定义、目标市场、竞品或替代做法、关键资源、复用意向和能力/模块边界六项输入，再展开具体问题。[产品研究指南](skills/research-design-kickoff/references/product-research-guide.md)细化产品形态、不同资源类型的限制、开源复用和实现路径。相关主题的省略或合并需要说明理由，不固定竞品数量或六模块架构。已知信息直接复用，未知公开事实转成研究任务，只有影响范围且须由用户决定的模糊点才需要澄清。

通用问题按自身需要选择主题。一份材料的简短解释可以保持一个任务；UNDERSTAND 输出解释及其边界，不制造候选排名。每个新任务明确目的、预期产出、证据质量要求、停止条件和真实依赖。独立研究者的输入包由权威任务书生成，避免出现第二份需要维护的研究计划。

研究阶段**支持 Agent Team 必须启用并使用；不支持时采用真实独立的手动 Session**。单任务可只设一个独立研究者，多份结果使用独立汇总上下文。主会话只接收协调回执和最终中立证据包，研究正文留在独立上下文。独立任务可以并行，共享预算的更新串行完成。具体交接见[研究派发协议](skills/research-execution/references/research-dispatch.md)。上下文声明和本地回执不能证明真实隔离或未登记的外部调用；手动 Session 缺少共享控制入口时只生成交接包，不能宣称已完成受控执行。

## 法庭如何保持隔离

| 步骤 | 谁读取正文 |
|---|---|
| 冻结中性的范围、证据和决策条件 | 主协调会话为干净的角色上下文准备引用 |
| 独立完成所有文稿，再整体封存 | 每个倡导者、红队和可行性评估者只读各自获准的中性输入 |
| 交换封存文稿，进行一至两轮质询 | 各角色会话读取交换记录；第二轮只处理仍可能改变决策的遗留问题 |
| 根据完整记录裁决 | 新的独立法官会话，与主会话和所有参与者分离 |
| 继续主工作流 | 主会话只读取安全状态、文件引用/哈希和最终中性结论 |

主会话不接收立场或辩论正文，也不担任法官。并发受限时角色可以排队。支持但被禁用或暂时故障的 Team 必须恢复；只有真实不支持才使用手动独立 Session。仅一个候选且已确认范围未要求法庭时，可直接评估。不存在单会话法庭降级。

手动模式提供可复制角色包。用户打开独立 Session，将完整结果直接保存至指定文件或转交给其他角色会话；主会话只收安全回执。详见[宿主要求](HOST_INSTRUCTIONS.md)与[法庭协议](skills/adversarial-option-selection/references/court-protocol.md)。

## 快速开始

提问、配置选择、需求确认与成果验收都使用**普通文字**，不用选项卡，也不设置回答期限。
首次需要联网但没有适用配置时，插件会说明缺少的能力，让你选择配置所需服务商、使用
已授权的宿主内置工具或离线处理。密钥在本地填写，无需发到聊天中。

关键问答后，插件先展示整理后的需求摘要，包括目标、研究重点、范围和重要假设；
**你确认该摘要后才开始调研任务设计与执行**。你可以稍后回复，待答问题和草稿引用会
保留在工作区。研究按核心问题与外围概览分配深度；多路线报告展示证据对照，明确实际
核实范围和缺口。报告先交付预览，你接受实际版本后才完成验收或进入后续决策。

使用能够完整加载技能文件与引用、读写本地产物、执行 Python 命令，并能进行澄清和文档验收的 AI 宿主。准备 Python 3.11+ 和该宿主 PATH 中的 `uv`。解压 `problem-navigator-2.4.0.zip`，保持 `skills/`、`mcp/` 与 `release.json` 同根，在该目录运行：

```sh
uv sync --locked --project mcp/web-research-mcp
```

首次准备可能下载依赖。随后让宿主执行：

> 完整读取此安装目录中的 `skills/problem-navigator/SKILL.md` 及其必需引用，遵循工作流，并在路由时加载相邻阶段技能。用中文回答。只使用这些记录：一场计划 30 分钟的会议用了 45 分钟，中途新增两个议题。不要联网。输出研究报告，区分事实、推断与未知。

安装位置不在宿主工作区时，指定绝对安装路径。原生技能发现可选，具备相应能力时可以明确读取文件；`$`、`/` 属于宿主快捷语法。离线研究选择 `NONE`，跳过服务商配置检查，不进行研究网络调用。宿主/模型连接与首次依赖下载另行适用。所提供的陈述保留来源，不自动视为已独立核实。

## 成果与语言

| 请求 | 端点与结果 |
|---|---|
| 理解问题 | `UNDERSTAND` → `RESEARCH_REPORT` |
| 确定通用方案 | `DECIDE` + `GENERAL` → 正式方案报告 |
| 设计完整产品/软件方案 | `DECIDE` + `PRODUCT_SOFTWARE` → PRD 与技术规格 |
| 仅产品需求 | `PRD_ONLY` → `01-prd.md` |
| 仅技术设计 | `TECHNICAL_SPEC_ONLY` → `01-technical-solution-spec.md` |
| 明确约定的规格包 | 可选 `FINAL_SPEC_PACKAGE` |

用自然语言说明目标。需要 PRD 时描述用户、行为、约束和验收需要；纯技术问题可要求仅技术规格。流程止于分析与设计，文档在明确接受前保持预览状态。

中文和英文同等支持。正文先遵循当前明确语言要求，再遵循适用的先前偏好，否则跟随当前请求。只限定最终文档的偏好不会改变访谈语言。机器字段、枚举、ID、文件名和原始引用保持不变。

## 网页研究、费用与宿主限制

网页研究使用用户自备的 Brave、Exa 或 Firecrawl 密钥，以及本地 stdio MCP 连接。每次 Core 调用只用一条明确路由，不静默切换服务商。获准的查询、公开 URL、域名和选项会发送给所选服务商，请勿加入机密材料。宿主内置研究需要覆盖相应范围的授权。共享调用预算计数操作，包括失败和宿主操作，不是金额上限。

MCP 提供研究工具，完整工作流还需要技能与本地文件/命令能力。纯聊天不能执行完整流程，仅支持远程 HTTP MCP 的宿主不能直接连接当前 stdio 服务。同一个包只包含一份共享核心及可选 Codex 元数据，详见 [Codex 指南](adapters/codex/README.zh-CN.md)，无需另下压缩包。可移植文件包不代表所有宿主都能一键安装。

校验覆盖结构、当前引用、封存记录与文件哈希；宿主能力和上下文声明仍依赖宿主或用户的真实观察。发现法庭内容泄漏后，该轮审查失效。这些控制不能证明线上研究服务质量或所有宿主都已通过端到端运行。

恢复时保留安全错误码、请求 ID 与工作流产物，报告中不要加入凭据和私人文档。仓库平台提供私密漏洞渠道时应使用该渠道。配置、具体控制与集成限制见 [HOST_INSTRUCTIONS.md](HOST_INSTRUCTIONS.md)，许可与署名见 [LICENSE](LICENSE) 和 [NOTICE.md](NOTICE.md)。
