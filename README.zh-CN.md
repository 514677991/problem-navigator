# Problem Navigator｜问题导航

把尚不清晰的通用问题或产品/软件问题，整理成有证据支撑的研究报告、决策与设计规格。由共享技能与本地 Python/MCP 研究核心组成，支持中文和英文。发行版本 **2.2.0**；研究 MCP **0.2.0**；[MIT 许可证](LICENSE)。

## 如何保障决策质量

- **先证据，后偏好。** 先定界问题，收集相关依据与反证，再澄清可能改变选择的用户价值取舍。
- **隔离的法庭审查。** 候选倡导者、红队与可行性评估者先独立完成完整立场文稿，全部封存后才交换；新的非参与法官根据封存记录裁决。支持 Agent Team 必须使用，不支持时由真实独立 Session 手动保留角色隔离。
- **让证据缺口可见。** 区分事实、有基础的推断、假设和未知。材料不足时定向补证、交付说明局限的部分报告或暂不选择，不靠辩论强造赢家。
- **按问题裁剪范围。** 通用问题围绕相关机制与约束；产品/软件问题先明确 What，再确定 How。可以只要 PRD 或只要技术规格，避免无关章节。
- **结论可追溯、可纠正。** 关联主张、来源、候选与需求；事实纠正会重开受影响研究，保留调用计数，使过期决策和文档失效。
- **诚实的文档验收。** 授权起草产生预览；正式发布需要接受实际文档，并检查当前关联和成员文件内容。

这些是流程控制与评审职责。结构检查和哈希不能证明事实真实、上下文确实独立或用户真的接受了文档。

## 法庭如何保持隔离

| 步骤 | 谁读取正文 |
|---|---|
| 冻结中性的范围、证据和决策条件 | 主协调会话为干净的角色上下文准备引用 |
| 独立完成所有文稿，再整体封存 | 每个倡导者、红队和可行性评估者只读各自获准的中性输入 |
| 交换封存文稿，进行一至两轮质询 | 各角色会话读取交换记录；第二轮只处理仍可能改变决策的遗留问题 |
| 根据完整记录裁决 | 新的独立法官会话，与主会话和所有参与者分离 |
| 继续主工作流 | 主会话只读取安全状态、文件引用/哈希和最终中性结论 |

主会话不接收立场或辩论正文，也不担任法官。并发受限时角色可以排队。支持但被禁用或暂时故障的 Team 必须恢复；只有真实不支持才使用手动独立 Session。仅一个候选且已确认范围未要求法庭时，可直接评估。不存在单会话法庭降级。

手动模式提供可复制角色包。用户打开独立 Session，将完整结果直接保存至指定文件或转交给其他角色会话；主会话只收安全回执。详见[宿主要求](HOST_INSTRUCTIONS.md)与[法庭协议](skills/adversarial-option-selection/references/court-protocol.md)。

## 快速开始

使用能够完整加载技能文件与引用、读写本地产物、执行 Python 命令，并能进行澄清和文档验收的 AI 宿主。准备 Python 3.11+ 和该宿主 PATH 中的 `uv`。解压 `problem-navigator-2.2.0.zip`，保持 `skills/`、`mcp/` 与 `release.json` 同根，在该目录运行：

```sh
uv sync --locked --project mcp/web-research-mcp
```

首次准备可能下载依赖。随后让宿主执行：

> 完整读取此安装目录中的 `skills/problem-navigator/SKILL.md` 及其必需引用，遵循工作流，并在路由时加载相邻阶段技能。用中文回答。只使用这些记录：一场计划 30 分钟的会议用了 45 分钟，中途新增两个议题。不要联网。输出研究报告，区分事实、推断与未知。

安装位置不在宿主工作区时，指定绝对安装路径。原生技能发现可选，具备相应能力时可以明确读取文件；`$`、`/` 属于宿主快捷语法。离线研究选择 `NONE`，跳过服务商配置检查，不进行研究网络调用。宿主/模型连接与首次依赖下载另行适用。所提供的陈述保留来源，不自动视为已独立核实。

## 成果与语言

| 请求 | 端点与结果 |
|---|---|
| 理解问题 | `UNDERSTAND` → `RESEARCH_REPORT` |
| 确定通用方案 | `DECIDE` + `GENERAL` → 正式方案报告 |
| 设计完整产品/软件方案 | `DECIDE` + `PRODUCT_SOFTWARE` → PRD 与技术规格 |
| 仅产品需求 | `PRD_ONLY` → `01-prd.md` |
| 仅技术设计 | `TECHNICAL_SPEC_ONLY` → `01-technical-solution-spec.md` |
| 明确约定的规格包 | 可选 `FINAL_SPEC_PACKAGE` |

用自然语言说明目标。需要 PRD 时描述用户、行为、约束和验收需要；纯技术问题可要求仅技术规格。流程止于分析与设计，文档在明确接受前保持预览状态。

中文和英文同等支持。正文先遵循当前明确语言要求，再遵循适用的先前偏好，否则跟随当前请求。只限定最终文档的偏好不会改变访谈语言。机器字段、枚举、ID、文件名和原始引用保持不变。

## 网页研究、费用与宿主限制

网页研究使用用户自备的 Brave、Exa 或 Firecrawl 密钥，以及本地 stdio MCP 连接。每次 Core 调用只用一条明确路由，不静默切换服务商。获准的查询、公开 URL、域名和选项会发送给所选服务商，请勿加入机密材料。宿主内置研究需要覆盖相应范围的授权。共享调用预算计数操作，包括失败和宿主操作，不是金额上限。

MCP 提供研究工具，完整工作流还需要技能与本地文件/命令能力。纯聊天不能执行完整流程，仅支持远程 HTTP MCP 的宿主不能直接连接当前 stdio 服务。同一个包只包含一份共享核心及可选 Codex 元数据，详见 [Codex 指南](adapters/codex/README.zh-CN.md)，无需另下压缩包。可移植文件包不代表所有宿主都能一键安装。

校验覆盖结构、当前引用、封存记录与文件哈希；宿主能力和上下文声明仍依赖宿主或用户的真实观察。发现法庭内容泄漏后，该轮审查失效。这些控制不能证明线上研究服务质量或所有宿主都已通过端到端运行。

恢复时保留安全错误码、请求 ID 与工作流产物，报告中不要加入凭据和私人文档。仓库平台提供私密漏洞渠道时应使用该渠道。配置、具体控制与集成限制见 [HOST_INSTRUCTIONS.md](HOST_INSTRUCTIONS.md)，许可与署名见 [LICENSE](LICENSE) 和 [NOTICE.md](NOTICE.md)。
